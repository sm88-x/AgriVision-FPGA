   双机需要：两台机器同网段、放行后端端口入站、电脑1 填电脑2 的 IP。

2. **没有录到 `data/evidence/demo/network_live_dual_pc.mp4`**：本机没有安装录屏工具（ffmpeg 不存在），

   也没有第二块屏幕可拍，所以只交了截图 + 日志 + 原始 CSV。录屏需在双机现场补。

3. **PYNQ 没有进入这条网络演示链路**：本次 `source=net` 的路径是

   “网络 JPEG → YOLO → Qt”，板端 `hardware/board` 路径代码未改动但当天没接板。

   演示时必须明确标注：当前这条网络链路是 **PC-only**，不是完整 FPGA 联调。

4. **协议缺时间戳**：任务书允许固定头/独立元数据，但 B 侧协议目前只有“长度 + JPEG”，

   所以只能测“收到帧之后”的处理耗时，测不了“采集→发送→接收→显示”的总延迟。

   建议 B 在帧头加 8 字节发送时间戳（需与 C 同步版本号）。

5. **“连接/断开”与“开始/停止”语义重叠**：当前都作用于同一个后端进程

   （连接 = 起服务并处理，断开 = 停服务），没有“只监听不处理”的独立状态。

   如需严格的四态控制，需要后端增加 `pause` 命令与状态机。

6. **Qt 侧没有网络异常自动重连**：断线由后端保持监听来完成，Qt 只显示状态；

   若后端进程本身崩溃，Qt 只会显示后端退出，需要人工点“重新开始”。

7. **FPGA 模式回执只在板卡源验证过代码路径**：`preset` 已写进请求、状态行会显示

   `src/software/fpga/dma/preset`，但当天没有接板，没能在真板上确认“换 preset 后输出确实变了”。

## 三、踩过的坑（后续别再踩）

1. `--conf` 是 **0~1 的小数**（默认 0.25）。传 `--conf 25` 会被界面按 ×100 换算成 2500、

   夹到 100 → 阈值 1.0 → 真模型一个框都不给（当天已复现并修正调用方式）。

2. 后端原本“先加载模型、后绑定端口”，模型加载期间 PC1 连接会被拒（10061）。

   已改为**先监听、再加载模型**，发送端可以立刻连上排队。

3. 后端写预览图必须原子写（先写 .tmp 再替换），否则 Qt 轮询时会读到半张图；

   该机制沿用 detection 适配器的 `atomic_write_json`/先写后换。

4. 帧号 `frame_id` 是 Qt 对齐“预览图 / 检测框 / 状态”的唯一键，出现跳号要当作丢帧记录，

   不能把跳号悄悄当成连续帧。
